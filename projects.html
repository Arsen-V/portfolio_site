Vulnerability management

Automated vulnerability risk-acceptance pipeline

Built at ElevateBio · Jun–Aug 2026

The problem. Two scanners produced overlapping vulnerability findings with no shared identifier and no concept of an SLA breach. Every quarter someone had to pull both lists by hand, reconcile them, decide what could be risk-accepted, and write a justification for each one. With an ISO 27001 audit coming, the backlog was in the thousands and the manual approach didn't scale.

What I built. A Python pipeline that runs weekly on GitHub Actions:

  • Pulls findings from CrowdStrike Falcon Spotlight and Vanta over OAuth, handling token refresh, rate-limit retries, and pagination
  • Merges and deduplicates across both sources
  • Enriches each CVE with exploitability metadata and scores it against a CVSS-vector rubric — internet exposure, attack vector, privileges required, user interaction, exploit status, CISA KEV membership
  • Auto-generates risk-acceptance justifications naming the specific compensating control (Palo Alto NGFW, CrowdStrike EDR/ITP, Netskope web filtering)
  • Flags actively exploited criticals and CISA KEV entries as patch-now rather than accepting them
  • Extends into an agentic assistant on Amazon Quick, letting engineers query live vulnerability posture and CVE detail — severity, exploitability, SLA status — in natural language instead of calling the APIs by hand

Outcome. Risk-accepted 1,611 vulnerabilities ahead of the ISO 27001 audit with a written, auditable justification attached to each, and separated out 370 that needed patching instead.

AI red team

Adversarial testing harness for LLMs and RAG pipelines

Personal project · In progress, expected Sep 2026 · Source

The problem. Organizations are putting internal documents behind RAG chatbots faster than they're testing them. The failure modes — indirect prompt injection through retrieved content, information disclosure across access boundaries, jailbreaks that survive system-prompt hardening — aren't caught by conventional application security testing.

What I built. A reproducible harness that runs adversarial test suites against self-hosted and hosted models:

  • Self-hosted Llama 3 via Ollama alongside hosted models, so the same suite can be compared across both deployment models
  • Test suites built with Garak, Promptfoo, and PyRIT, mapped to the OWASP LLM Top 10
  • Measured success rates per technique rather than pass/fail, so mitigations can be compared
  • A demonstrated indirect prompt-injection attack against a RAG vector store, plus a mitigation that measurably reduced the attack success rate
